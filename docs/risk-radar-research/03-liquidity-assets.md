# Protocol liquidity, TVL and depeg risk

## Verified scope and data semantics

DefiLlama's official API documentation states that the free API requires no key and uses `https://api.llama.fi` for public endpoints. The documented free TVL endpoints include `/protocols`, `/protocol/{protocol}`, `/tvl/{protocol}`, `/v2/chains`, and `/v2/historicalChainTvl/{chain}`. The `/protocols` schema includes `id`, `name`, `slug`, `chains`, `tvl`, `chainTvls`, `change_1d`, and `change_7d`; live responses also currently expose `change_1h` for many rows. Protocol detail returns historical `chainTvls[chain].tvl` points as `{date,totalLiquidityUSD}`. Chain history returns `{date,tvl}` points. [1]

DefiLlama defines protocol TVL as the USD value of coins held in protocol contracts and chain TVL as the sum of protocol TVL. Borrowed coins, protocol-owned tokens, and several double-counted or unproductive categories are excluded from core TVL. Therefore TVL is not a direct withdrawal ledger. Its own methodology says USD TVL can fall solely because asset prices fell, and defines USD inflows as balance changes valued at asset prices to separate deposits/withdrawals from price effects. [2]

The keyless stablecoin API is documented under `https://stablecoins.llama.fi`: `/stablecoins`, `/stablecoincharts/all`, `/stablecoincharts/{chain}`, `/stablecoin/{asset}`, `/stablecoinchains`, and `/stablecoinprices`. Live checks verified that `/stablecoins?includePrices=true` returns `peggedAssets[]` with `id`, `name`, `symbol`, `gecko_id`, `pegType`, `priceSource`, `pegMechanism`, `circulating`, `circulatingPrevDay`, `circulatingPrevWeek`, `circulatingPrevMonth`, and per-chain `chainCirculating[chain].current/circulatingPrevDay/...`, each containing `peggedUSD`. `/stablecoincharts/Near` returns daily records with `date`, `totalCirculating.peggedUSD`, `totalCirculatingUSD.peggedUSD`, and `totalMintedUSD.peggedUSD`. `/stablecoinprices` returns dated records with a `prices` map keyed by stablecoin identifiers. [1]

The keyless DefiLlama coins API is documented with `/prices/current/{coins}`, `/prices/historical/{timestamp}/{coins}`, and `/chart/{coins}`. A live request to `https://coins.llama.fi/prices/current/coingecko:tether,coingecko:usd-coin` returned `coins[id].price`, `symbol`, `timestamp`, and `confidence`; this is suitable for a price-effect control and a depeg observation, but it is not a pool-level liquidity or redemption-price feed. [1]

NEAR RPC is useful for finalized chain health and contract-state evidence, not for a protocol TVL number by itself. Official docs specify `status`, `network_info`, and `validators`; the account query returns `amount`, `locked`, `storage_usage`, `code_hash`, `block_hash`, and `block_height`. `view_state` returns paginated base64 key/value records with a consistent `block_hash`/`block_height`, and `call_function` can read a contract's view methods. [3] [4]

## Candidate live signals

1. **NEAR chain TVL drawdown, price-controlled.** Use `GET https://api.llama.fi/v2/historicalChainTvl/Near` (`date`, `tvl`) for the documented daily series, and `GET https://api.llama.fi/v2/chains` (`name`, `tvl`) for current spot. Use existing DefiLlama TVL access now. Impact: high if a broad, persistent fall is confirmed. Source confidence: medium, because the series is an aggregator's modeled protocol TVL and daily granularity cannot prove a same-hour withdrawal.

2. **Protocol-level TVL drop on NEAR.** Poll `GET https://api.llama.fi/protocols`; select rows whose `chains` contains `Near`, then retain `slug/name`, `tvl`, `chainTvls.Near`, and observed `change_1h/1d/7d`. For historical attribution, use `GET https://api.llama.fi/protocol/{slug}` and inspect `chainTvls.Near.tvl[].totalLiquidityUSD`; this is available now through the existing DefiLlama feed. Impact is high when several large NEAR protocols fall together. Source confidence is medium: protocol coverage and adapter methodology differ, and the public historical endpoint is daily.

3. **Stablecoin supply contraction on NEAR.** Use `GET https://stablecoins.llama.fi/stablecoins?includePrices=true`, summing `chainCirculating.Near.current.peggedUSD` across the selected asset IDs, or use `GET https://stablecoins.llama.fi/stablecoincharts/Near` (`totalCirculating.peggedUSD`, `totalMintedUSD`). This is available now as a free public endpoint. Impact is medium/high only when contraction is large and not explained by a protocol migration or bridge coverage change. Source confidence is medium: this is supply/coverage evidence, not proof of user withdrawals from a particular protocol.

4. **Stablecoin market depeg.** Use `GET https://stablecoins.llama.fi/stablecoinprices` (`date`, `prices[asset-id]`) and/or `GET https://coins.llama.fi/prices/current/coingecko:<id>` (`price`, `timestamp`, `confidence`). This can run now with a free public endpoint, but the stablecoin price key must be mapped to the exact asset ID; do not treat a ticker collision as proof. Impact is high for a major collateral asset and lower for a small token. Source confidence is medium/high for the observed market quote, but lower for solvency inference because an exchange/aggregator quote is not a redemption guarantee.

5. **Collateral coverage proxy.** Where the collateral token has a DefiLlama stablecoin record, compare `chainCirculating.Near.current.peggedUSD` with its market price and, if available, `chainBalances.Near.tokens[].circulating.peggedUSD` from `/stablecoin/{asset}`. This can be added via the free endpoint. It is not a dependable protocol reserve ratio: lending positions, oracle prices, and liabilities are not included.

6. **On-chain confirmation of a suspected contract change.** Use the existing FastNEAR public RPC `query` with `request_type=view_account` for the protocol account and finalized `amount`, `locked`, `storage_usage`, `code_hash`, `block_height`; use `view_state` or `call_function` only when the contract's state schema/view method is known. This can run now for named contracts, but it requires a maintained protocol/account/asset registry and ABI-aware decoders. RPC block/account changes alone do not identify withdrawals or collateral coverage.

## Testable short-window rules

- **Price effect versus balance/withdrawal effect (preferred rule):** for a protocol or chain, let `TVL_t` be USD TVL and let `P_t` be the relevant asset price vector. Over a matched window, compute `TVL_return = TVL_t/TVL_0 - 1`. If raw token balances are available from a protocol adapter, compute `balance_value_return = sum((B_t-B_0)*P_0)/sum(B_0*P_0)` and `price_effect = sum(B_0*(P_t-P_0))/sum(B_0*P_0)`. Flag **observed liquidity stress** only when `balance_value_return <= -0.10` over 24h (or `<= -0.05` over 6h with at least two observations) and the price control is not comparably negative. Flag **price-driven TVL loss** when `TVL_return <= -0.10` but `balance_value_return > -0.02` and the price effect explains at least 80% of the TVL change. These thresholds are operational screening rules, not validated probabilities. The free public protocol token-breakdown chart shown in the docs is API-plan-only, so this exact decomposition cannot run from the currently connected feeds unless raw balances are obtained from a known contract view or a free adapter source.

- **Cross-protocol concentration rule:** among NEAR protocol rows from `/protocols`, calculate each `chainTvls.Near / sum(chainTvls.Near)`. Flag **high-impact coordinated stress** when the top three protocols together lose at least 15% of their prior 24h NEAR TVL and at least two independently lose at least 10%; require the chain series/current spot to corroborate. Evidence would be two timestamped `/protocols` snapshots plus the affected slugs and `chainTvls.Near` values. This can be added using the free endpoint, but a true sub-day test requires storing snapshots.

- **Protocol TVL versus chain TVL separation:** flag a **protocol-specific event** when one protocol's `chainTvls.Near` falls at least 15% in 24h while aggregate NEAR TVL falls less than 5% and the NEAR reference price moves less than 5%. Flag **ecosystem stress** when aggregate NEAR TVL falls at least 10% and at least three material protocols each fall at least 10%. Evidence must include all denominators and the same observation times; otherwise report only a candidate, not an alert.

- **Stablecoin depeg severity:** for a USD-pegged asset, compute `abs(price-1)`. **Severe observed depeg:** at least 3% for two consecutive samples or at least 5% once with `confidence` present and non-stale. **Moderate:** 1–3% for two consecutive samples. Require the asset's `pegType` to be `peggedUSD`, record `priceSource`, and exclude missing/stale prices. A depeg alert is an observed test result only; never emit “not yet observed” as an alert.

- **Supply/coverage change versus price effect:** from `/stablecoincharts/Near`, compute `supply_return = totalCirculating_t/totalCirculating_0 - 1` and `coverage_gap = totalMintedUSD - totalCirculatingUSD`. Flag **supply contraction** at `supply_return <= -10%` over 7 daily points, or `<= -5%` over 2 daily points only as a watch. Treat a simultaneous `totalMintedUSD`/`totalCirculatingUSD` discontinuity without matching market-price movement as a possible coverage/methodology change, not a withdrawal alert. Evidence must include the raw daily fields and asset-level `/stablecoins` rows.

- **Collateral stress conjunction:** flag **high-impact collateral risk** only if (a) the collateral stablecoin has an observed severe depeg, (b) its NEAR circulating supply or the affected protocol's raw balance falls at least 10% in the same window, and (c) the source timestamps overlap. A price move without a balance/supply contraction is market/valuation impact, not evidence of a run; a supply contraction without a depeg is liquidity/coverage impact, not proof of insolvency.

- **NEAR RPC confirmation:** after a DefiLlama signal, query finalized FastNEAR `status` and relevant `view_account`/`view_state` at the returned `block_height` or `block_hash`. Evidence of an RPC-side issue is a stale/non-advancing finalized height or inconsistent block identifiers; it is not protocol liquidity evidence. A contract `code_hash` change or known state field discontinuity can corroborate a migration/upgrade explanation, but only with an ABI/schema mapping.

## Availability and limitations

The currently connected FastNEAR RPC, FastNEAR Neardata finalized samples, CoinGecko history, DefiLlama spot prices, and DefiLlama chain TVL can run network-health, market-price, daily chain-TV​​L, current protocol-TV​​L, and stablecoin supply/price checks. They cannot, without an additional protocol/account registry and decoded contract reads, prove arbitrary NEAR DeFi withdrawals, lending utilization, liquidation queues, pool reserves, oracle health, or collateralization ratios.

A free DefiLlama endpoint can be added for protocol and stablecoin snapshots, but short-window rules need timestamped snapshots retained by the application. DefiLlama's documented inflow endpoint is API-plan-only, and its documented token-breakdown chart is API-plan-only; do not claim those exact raw inflow/balance decompositions are available on the current no-key feed. CoinGecko's current official documentation directs users to a Demo API with limited endpoints and rate limits and a Pro reference; therefore the connected CoinGecko public/history feed should be treated as a supplied input, not assumed to provide unlimited keyless live polling. [5]

No risk alert is asserted in this note. An implementation must emit an alert only after the raw endpoint response satisfies a rule above, with timestamp, endpoint, fields, denominator, and source-confidence label attached.
