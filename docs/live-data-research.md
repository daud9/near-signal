# Live data research and provider decisions

## Connected public sources

NEAR's [RPC provider list](https://docs.near.org/api/rpc/providers) identifies FastNEAR's `https://free.rpc.fastnear.com` as a public mainnet endpoint with a free tier. Its numeric free-tier request limit is unpublished; archival access is separate. The app needs current/finalized reads, not historical archive queries. The [NEAR block/chunk reference](https://docs.near.org/api/rpc/block-chunk) documents finalized block and chunk requests, and the [network RPC reference](https://docs.near.org/api/rpc/network) documents status and validator reads.

A browser-origin probe allowed the FastNEAR JSON `POST` CORS preflight and returned `chain_id: mainnet` for `status`. A live finalized-block verification requested every referenced shard and validated the documented chunk fields before accepting a sample. No implementation check depends on an undocumented separate chunk `block_hash` field. Missing or mismatched current chunks withhold a full transaction total.

The legacy `https://rpc.mainnet.near.org` hostname did not permit browser CORS in the app test and returned HTTP 429 with a deprecation notice during a direct probe. Other no-key candidates tried from this environment included `near-rpc.publicnode.com`, `1rpc.io/near` and `near.drpc.org` (403), a Tenderly URL (404), and `rpc.near.gateway.fm` (DNS failure). These are environment-specific results, not proof that the providers are universally unavailable. Do not load-test shared public endpoints.

[CoinGecko's keyless API guidance](https://docs.coingecko.com/docs/keyless-public-api) and [simple-price reference](https://docs.coingecko.com/demo/reference/simple-price) describe timestamped market fields. Its keyless service is intended for testing, open-source and educational use, has a shared dynamic request limit and calls for attribution. The app fetches current market data and [daily market-chart data](https://docs.coingecko.com/demo/reference/coins-id-market-chart) on load or user refresh; it does not poll these endpoints in the background.

[DefiLlama's NEAR spot endpoint](https://coins.llama.fi/prices/current/coingecko:near) supplies a separately timestamped price check. Its [historical NEAR TVL endpoint](https://api.llama.fi/v2/historicalChainTvl/near) returns daily USD snapshots. Its [metric definitions](https://docs.llama.fi/analysts/data-definitions) describe TVL as an asset stock, not a flow. Neither source establishes net investment or reconciled bridge/Intents flows.

## Why daily user and flow data remain unavailable

- [NearBlocks API plans](https://nearblocks.io/apis) describe a personal-use free plan; its [Terms](https://nearblocks.io/terms) require prior written consent for third-party apps and prohibit automated collection. The app makes no NearBlocks requests. Its legacy API docs announced v1/v2 shutdown for 22 November 2026.
- [Pikespeak's OpenAPI](https://api.pikespeak.ai/openapi.json) includes a daily active-account endpoint, but data access requires an API key. No key is configured. A provider-reported address count would not establish verified people, retention or organic adoption.
- FastNEAR's indexed history endpoints are separate from its public RPC and require an API key. No key or authorized query is configured. Public RPC and Neardata block reads do not provide daily account cohorts or archive completeness.
- The [NEAR Intents Explorer API](https://docs.near-intents.org/integration/distribution-channels/1click-api/explorer/introduction) requires partner JWT access and covers 1Click Swap records, not all Intents activity. A JWT must not be embedded in browser code.
- [Goldsky's NEAR offering](https://goldsky.com/chains/near) is an indexing product, not a verified anonymous public stats API. The [Bitquery supported-chain list](https://docs.bitquery.io/docs/blockchain/supported-chains/) did not establish the required NEAR daily-history feed. [NEAR Lake](https://docs.near.org/data-infrastructure/tutorials/running-near-lake/run-near-lake) stopped receiving new blocks on 24 March 2026.
- DefiLlama's [bridge API documentation](https://api-docs.defillama.com/) marks bridge methods as paid-plan endpoints. Bridge catalogue and volume requests returned a paid-plan response. Adding that endpoint would not by itself resolve direction, coverage or double-counting across both bridge legs.

Therefore daily account cohorts, user retention, daily transaction trends, historic fee series, complete application concentration, reconciled bridge/Intents net flows, multi-epoch validator history and long-run infrastructure history remain unavailable. The product withholds the overall score rather than presenting a proxy as a missing measure.

## Architecture reference review

Fincept Terminal's repository metadata declares AGPL-3.0 and its LICENSE contains GNU Affero GPL version 3. Its [Python contributor guide](https://github.com/Fincept-Corporation/FinceptTerminal/blob/main/docs/PYTHON_CONTRIBUTOR_GUIDE.md) separates screens, services and data sources and returns structured results; its [architecture guide](https://github.com/Fincept-Corporation/FinceptTerminal/blob/main/docs/ARCHITECTURE.md) keeps network work out of module import. NEAR SIGNAL applies those ideas in its existing JavaScript design: `src/app.js` renders, `src/data.js` owns source adapters/status, `src/analytics.js` contains pure calculations, and imports perform no network requests. No Fincept code, runtime or dependencies were copied.

The repository's [CoinGecko wrapper](https://github.com/Fincept-Corporation/FinceptTerminal/blob/main/fincept-qt/scripts/coingecko.py) uses the same market endpoints already called by NEAR SIGNAL, adding no new evidence. Its [DefiLlama wrapper](https://github.com/Fincept-Corporation/FinceptTerminal/blob/main/fincept-qt/scripts/defillama_data.py) does not establish complete NEAR-directed net flows. The project keeps its smaller JavaScript architecture and avoids AGPL code reuse.
